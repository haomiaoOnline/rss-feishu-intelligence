# RSS 多群组情报管理台：需求规格、验收条件与实施计划

版本：v3 设计基线（2026-10-22）。状态：**需求冻结后先开发、离线验证，再按门禁部署**。

## 1. 场景与目标

现状：66 个来源（X、通用 RSS/Atom），Git `config/feeds.json` 管理来源；单一 Feishu 群和全局 `articles.delivered/batch_id` 发送状态，服务器有 SQLite 持久化和每小时 timer。当前方案不能让不同群订阅不同来源，也不支持在网页上改动，不可直接把单个 webhook 替换成列表。

用户目标：通过网页完成“添加/选择信源 → 创建推送分组 → 配置该组飞书自定义机器人 → 开启推送 → 查看发送状态”，不同组可订阅交叉的源，一篇文章对各目标独立判重，同群不重复，互不影响。

**释义**：本期“飞书智能体群组”实现为现有 Feishu 自定义群机器人 webhook（需要「RSS情报」关键词）；Feishu 应用 Open API 自建应用、OAuth、多租户管理员暂不包含在 P0。

## 2. 用户故事与交互

- 管理员打开安全的本地网页，看到来源总数、启用分组数、待发量、最近错误和任务健康。
- 左侧「信源」：搜索/按类型及状态筛选，添加 X handle 或 HTTPS RSS URL，编辑显示名/分组，启停/删除（先告知影响）；给出校验结果及首次订阅默认“不补发旧帖”。
- 左侧「推送分组」：新建分组（显示名称、唯一 ID/备注、启用开关），勾选多个信源，设置独立机器人 webhook、查看是否已配置但永不显示回完整凭据，设置每批上限及最短发送间隔。
- 左侧「发送记录」：每组显示最近时间、成功/失败/不确定次数、上次发送篇数；不确定状态不可一键重发。
- 「机器人测试」：明确一次点击、二次确认，发送带【测试】的标识卡片，用户在飞书群人工确认；从不触发历史消息补发。
- 未配置 webhook 或分组无信源时允许草稿保存，但不允许启用投递。

## 4. 核心状态与兼容性

**Source**：独立规范化 X handle 或 HTTPS URL，与已有 `feeds.json` 来源键兼容。新增时只从首次抓取成功后的新文章参与投递。

**Group**：唯一稳定 group_id、name、enabled、源列表、独立 webhook secret 引用、批量限额/间隔。可配置多个群，同一个来源允许被多个群选中。

**GroupMembership**：`(group_id, source_id, active_since)`，只接收绑定创建后的新发现文章，不把几个月前的历史帖倒灌新群。

**GroupDelivery**：`UNIQUE(group_id, article_id)`，存 pending/retry/sending/sent/ambiguous；每组独立 outbox & sent timestamp。源同属两组时应生成两个互不关联的 delivery；旧全局 `articles.delivered` 状态不得作为多组已发判定。

**Legacy**：原 RSS 群保持原 v4 投递路径和已发队列；v3 的新 Group 不替代旧逻辑直到显式迁移，避免旧 batch 再送一次。界面将原群标为“系统保留/旧通道”，只读状态；将其改造为可编辑普通组需单独完整迁移验收。

## 5. 安全和可访问性

- 默认只在服务器 `127.0.0.1` 绑定管理台；通过现有 SSH 本地端口转发访问，不公开任何管理端口或新公网地址。
- 管理台需管理员口令/令牌验证、session HttpOnly SameSite cookie、CSRF token、Origin 校验，禁用缓存、严格 CSP、速率限制、写入审计。
- Webhook 存储于服务器 Git 目录外、0600 权限，不在 SQLite 明文回显/日志/HTML、不得经 API GET 读回。
- RSS 输入执行原先的 HTTPS/域名防 SSRF 校验；发送目标只允许经验证的 `open.feishu.cn` 或 `open.larksuite.com` webhook。
- 所有管理员操作按事务提交，服务脚本共享 flock；生产迁移前 SQLite 在线备份，失败一键切回旧版本，原日报任务不可被修改。

## 6. 实施顺序与阶段门

1. **需求门**：编写本文、核对源代码真实约束和双 Agent 审查；明确 scope 和所有 Fxx 验收条件。
2. **基础后端门（F04–F08、F11）**：分组模型、订阅绑定、独立 outbox、遗留兼容。隔离/幂等/备份/恢复测试通过后 Git commit。
3. **管理页面门（F01–F06、F10）**：HTML 交互、管理认证、安全校验，HTTP 集成测试与浏览器操作通过后 Git commit。
4. **编排上线门（F02、F03、F09、F12）**：将页面更改接入抓取名单；修改 Git 自动同步冲突，文档化安装、升级、回滚与私有访问。离线测试与真机自测后 Git commit。
5. **发布门（F13）**：保留旧日志和 SQLite，先观测、备份、staging、部署；确认新旧 RSS 分组均可靠后 push GitHub 并记录提交。凡需用户本人在飞书群确认消息或公网开放/提供新 webhook 的步骤为人工门禁。

## 7. 明确不做

- 不自动上传新的飞书机器人密钥，不自动创建 Feishu 群或飞书应用。
- 不开放公网后台、不在 Git 明文放任何真实 Webhook、Cookie 或 SQLite。
- 不重发现有已 sent/ambiguous 批次；不对所有旧帖做多群补发。
- 不自动将历史 v4 群变成普通多群并双重发送。

## 8. 完成定义

本期 P0 完成 = 可通过网页创建至少两个分组，分别选择不同信源、配置独立 webhook 并测试（mock + 用户飞书群确认），新增文章按各组路由且各组各发最多一次、原群状态不变、后端重启不丢配置，未授权操作和非法输入被拒绝，所有 P0 测试通过，本地与远程 Git 对齐，操作文档足以让其他 Agent 重建和回滚。
